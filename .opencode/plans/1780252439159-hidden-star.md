# Plan: Fix CLI Help System & Dispatch

## Bugs Addressed

| # | Input | Current Output | Expected |
|---|-------|---------------|----------|
| 1 | `icu --help` / `icu -h` | `Unknown command: --help show` | Global help listing |
| 2 | `icu ftp --help` | Global help listing | Resource-specific help (usage per action) |
| 3 | `icu activities` (no action) | `Unknown command: activities show` | Resource-specific help (smart default) |
| 4 | `icu config diagnose` | Outputs API key fingerprints/lengths | Gate behind `--verbose` flag |

## Design Decisions

- **Resources with `show` action** (`athlete`, `ftp`, `config`, `activity`): default `show` still calls API — no change.
- **Resources without `show` action** (`activities`, `curves`, `wellness`, `events`, etc.): smart default shows resource-specific help instead of "Unknown command: X show".
- **Config diagnose**: `--verbose` flag added; without it, only shows resolved source names (not fingerprints/lengths).
- **Testability**: Extract `main()` body into `run(args, stdout, stderr) int` to enable testing help output and dispatch.

## Files to Modify (in order)

### 1. `cmd/icu/main.go` — Core refactor

**Changes:**
- Add `"io"` to imports
- Replace `main()` with thin wrapper: `os.Exit(run(os.Args, os.Stdout, os.Stderr))`
- New `run(args []string, stdout, stderr io.Writer) int`:
  - Pre-scan for `--help`/`-h`/`help` before resource detection
  - If `--help`/`-h` in position 1 (before resource): global help, return 0
  - If `--help`/`-h` in later position with known resource: resource-specific help, return 0
  - Smart default: if `action == "show"` and resource lacks `"show"` action → resource-specific help, return 0
  - Returns exit code (0 or 1), never calls `os.Exit()`
  - All `os.Stderr` writes → `stderr io.Writer`
- `executeCommand()`: signature returns `int`; receives `stdout, stderr io.Writer`; `os.Exit(n)` → `return n`; `fmt.Fprint(os.Stderr,...)` → `fmt.Fprint(stderr,...)`
- `printHelp()`: signature changes to `printHelp(registry *CommandRegistry, w io.Writer, resource string)`:
  - `resource == ""` → global help (unchanged format)
  - `resource != ""` → header `"Commands for <resource>:\n"` + per-action `Usage` + `Description`
- Remove `osStdout()` usage from help path

## Edge Cases Handled

- **`icu --help`**: Position 1 is `--help` → pre-scanned before resource detection → global help
- **`icu -h`**: Same as `--help`, detected by `parseFlags` correctly since it's not a reserve word
- **`icu <resource> --help`**: Args pre-scan finds `--help` at position 2+ → resource-specific help for known resource
- **`icu bogus --help`**: Resource unknown, `--help` still triggers global help (user intent is clear)
- **idFirst resources** (`activity`, `shared-event`): Unchanged dispatch, `--help` still detected
- **Backward compat**: `Command`, `CommandRegistry`, `parseFlags`, all `cmd_*.go` registration functions untouched
