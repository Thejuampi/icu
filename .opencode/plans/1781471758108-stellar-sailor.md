# Plan: Soporte completo de endpoints Zepp (paridad con m4ary/zepp-health-cli)

## Objetivo

Extender el subcomando `zepp` del CLI de `icu` para soportar **todos los endpoints/presets que expone `m4ary/zepp-health-cli`**, manteniendo la arquitectura actual (functional core / imperative shell), cobertura de tests >= 90%, linting limpio y documentación actualizada.

## Constraints del proyecto

- Zero dependencias externas (solo stdlib de Go).
- Functional core (`types.go`, `auth.go`, `urls.go`, `output.go`) puro; shell (`client.go`, `main.go`, `cmd_*.go`) con IO/HTTP/CLI.
- Cobertura de tests >= 90%.
- `go vet`, `golangci-lint`, `gofumpt` limpios.
- TDD: test fallando primero.
- Documentación (`docs/cli-reference.md`, `docs/library.md`, `README.md`) actualizada junto con el código.
- No exponer secrets en código ni tests.
- Conflict documented: `AGENTS.md` KISS/YAGNI says commands must map to Intervals.icu endpoints, but `zepp` maps to Zepp/Huami endpoints. Follow the higher-precedence quality gates and document as a separate read-only Zepp data source.

## Decisiones de diseño

1. **Nomenclatura de comandos:** Se usa convención `icu` (recurso-acción, kebab-case, descriptivo). Se documenta un mapeo a nombres de m4ary en `docs/cli-reference.md` para usuarios que migran. No se renombran comandos existentes.
2. **Flags de fecha:** Se mantienen `--oldest` y `--newest` por consistencia con los comandos `zepp` actuales (no se migra a `--start/--end`).
3. **Comando genérico `events`:** Se agrega `icu zepp events --preset <name>` como escape hatch y para paridad con m4ary. Los presets más usados también tienen comandos dedicados.
4. **Recursos duplicados:**
   - `heart-rate`: un solo comando con `--source band|app`; default `band` preserva el comportamiento actual (`band_data.json`). `--source app` usa `/users/{id}/heartRate`.
   - `blood-pressure`: un solo comando `zepp blood-pressure` con `--source watch|user`; default `watch` usa `/v2/users/me/events` (`blood_pressure/real_data`), `--source user` usa `/users/me/bloodPressure`.
   - `summary`: se conserva `zepp summary` actual (decodifica `band_data.json`). Se agrega `zepp health-summary` para el endpoint V2 `DailyHealth/summary` de m4ary.
5. **`second-heart-rate`:** MVP = solo devolver el file index (timestamps + URLs COS). No se descargan ni parsean blobs en este plan.
6. **Multi-sport:** Se extienden `zepp workouts` y `zepp workout` con `--sport <name|id>`; default `run` para backward compatibility. No se agrega `run-history` como comando separado.
7. **Slices:** Se implementa en 7 slices independientes, cada uno buildeable, testeable y documentable por separado.

// V2EventPreset registra un preset del endpoint /v2/users/me/events.
type V2EventPreset struct {
    Name      string // command-friendly, e.g. "body-battery"
    EventType string // e.g. "Charge"
    SubType   string // e.g. "real_data"

// ZeppV2Event es la salida genérica del comando `zepp events`.
type ZeppV2Event struct {
    Timestamp int64            `json:"timestamp"`
    Date      string           `json:"date"`

    SubType   string           `json:"subtype,omitempty"`
    Value     float64          `json:"value,omitempty"`
    Extra     map[string]any   `json:"extra,omitempty"`
}

## Estrategia de tests

- **Cliente:** `httptest.NewServer` con `newZeppTestServer`/`newTestZeppClient`. Un test por endpoint: verifica path, query, headers, decodificación, errores 5xx, token faltante, `code != 1`.
- **Decodificadores:** table-driven tests con payloads válidos, vacíos, campos extra, malformados.
- **CLI:** `withZeppTestEnv` + `newZeppMockServer` + `captureStdout`. Un test end-to-end por slice; los comandos restantes se testean con mocks directos.
- **Coverage:** mantener lógica en decodificadores/URL builders puros para maximizar cobertura sin depender de muchos tests CLI.
- **Backward compatibility:** tests que prueben `zepp workouts` y `zepp heart-rate` sin flags nuevos mantienen el comportamiento actual.

## Riesgos y notas

- **Host de `/v2/users/me/events`:** m4ary usa el host regional de data para V2 events; icu actualmente separa events host (`api-mifit.zepp.com`). Se debe verificar empíricamente en Slice 1 y, de ser necesario, agregar override o usar `dataHost` para V2.
- **Variabilidad de respuestas por modelo/región:** Zepp devuelve shapes distintos según reloj/región. Los decodificadores deben ser tolerantes (`omitempty`, `json.RawMessage` para nested desconocido).
- **Cobertura:** nuevos comandos que son solo wiring pueden bajar el total. Mitigar con tests de decodificadores y URL builders.
- **`second-heart-rate`:** los URLs COS pueden contener tokens temporales. Documentar que el output no debe compartirse.
- **Backward compatibility:** `workouts` sin `--sport` debe seguir llamando `/v1/sport/run/history.json`.
- **Linters:** `lll`, `gocyclo`, `dupl`, `paralleltest`, `testpackage`, `wrapcheck` requieren atención. Usar `//nolint:` justificado cuando sea necesario.
